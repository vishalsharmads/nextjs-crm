# Production-readiness review (November 2026)

Scope: the whole product at main `14e3b50` (phases 0–10): API logic and security, web UI/UX, search, settings, operations, and feature gaps against modern CRMs. Four focused reviews read the code; every item below cites code that was read. The top items were re-checked by hand. Nothing was changed by the review itself. Fixes are planned in [phase 11](../plan/phase-11.md); feature gaps in phases 12–18 ([roadmap](../roadmap.md)).

## Verdict

The foundations are strong: scoping and 404s, field visibility on records, parameterised SQL, audit triggers, encryption with a key ring, CSRF and token handling, backups with restore drill, CI with E2E. **It is not production-ready yet** because of a small number of privacy and data-integrity defects (automations, conversion, merge), missing security headers on the SPA in the shipped nginx config, search that will not scale or find custom values, and operational gaps (crash handling, job recovery, release rollback, production config checks). All are fixable in one hardening phase (about 3–4 weeks).

## Should fix soon (phase 11c–11e)

**Search** (biggest UX gap): ⌘K searches names only, OR'd `LIKE` defeats the FULLTEXT index, no relevance order, 5 hits per type, the palette re-filters server hits on the client, no debounce, entity badge ignores vocabulary, no results page. Fix: separate FULLTEXT and prefix queries, score ordering, searchable text custom fields (visibility-aware), activities and notes (as the assistant's `search_text` already does), debounce, `shouldFilter` off, a full results page.

**API correctness**: scheduled automations stop silently at 500 records; Kanban columns can be empty when one stage is big (one global limit); webhook deliveries lost on restart and not claimed atomically; CSV export ignores backpressure, uses OFFSET and has no cap; relation inputs not scope-checked; timeline lacks `logAccess` and the activities permission; dashboard totals add mixed currencies; import upload parsed before the permission check and xlsx size checked after unzip; user directory exposes all emails to any principal; digest claimed before sending; forecast buckets in UTC; locked accounts reveal themselves.

**Web**: no unsaved-changes guard on any settings page; several settings lists show "empty" on a failed load (automations, compliance, commerce, vocabulary, pipelines); `window.confirm` in eight module actions; literal English in settings and the palette; very large settings files (automations 1,158 lines) bundled together; notification polling in background tabs.

**Operations**: in-memory rate limits and caches assume one API process (document it, or Redis store and pub/sub invalidation); scheduled tasks without Redis need a MySQL `GET_LOCK` fallback; no SMTP test or bounce suppression; no `npm audit`/Dependabot in CI, and exceljs is unmaintained (deprecated `fstream`, `uuid@8`); fixed pool of 10 (`DB_POOL_MAX`); readiness ignores Redis and storage; request id accepted unchecked; backups not scheduled or monitored; no nginx `limit_req`.

One API test failed once in the first half of the suite during the phase 10 checks and passed on two reruns. Identify it in phase 11 (run the half in a loop).
